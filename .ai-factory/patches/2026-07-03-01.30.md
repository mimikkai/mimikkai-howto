# Fix playground: Cyrillic encoding, duplicate keys, browser visualization

**Date:** 2026-07-03 01:30
**Files:** lib/playground/parse-mim-lua.ts, components/playground/step-processing.tsx
**Severity:** high

## Problem

Three bugs in the playground feature:

1. **Garbled Cyrillic text** — `lua-in-js` uses `encodingMode: 'x-user-defined'` which maps bytes 0x80-0xFF to U+F7xx. The `escapeNonAsciiForLua` function converted non-ASCII chars to `\ddd` byte escapes, but inside Lua `[[ ]]` long strings, escape sequences are NOT processed — they're treated as literal text. This caused all Cyrillic text from `mim.description`, `mim.prompt`, and `mim.entry` fields to display as garbled `Ð¢Ñ` sequences.

2. **Duplicate React keys** — When "Запустить заново" was clicked in step-processing, `logIdRef` was not reset, causing key collisions since the counter continued from its previous value while the `logs` state was cleared.

3. **No browser visualization** — Step 4 only showed text logs and a table, with no visual indication that the agent was working "in a browser". Users couldn't understand what was happening.

## Root Cause

1. Lua `[[ ]]` long strings don't process `\ddd` escape sequences, so `escapeNonAsciiForLua` produced literal `\208\160` instead of byte values inside long strings. Fix: `convertLongStrings()` rewrites `[[ ]]` to `" "` quoted strings BEFORE escaping.

2. `handleStart` in step-processing cleared `setLogs([])` but forgot to reset `logIdRef.current = 0`.

3. The original implementation had no browser panel — only text logs.

## Solution

1. Added `convertLongStrings()` function that converts Lua long bracket strings `[[...]]` (including `[=[...]=]`) to regular `"..."` quoted strings with proper escaping of `\`, `"`, newlines, and tabs, BEFORE applying `escapeNonAsciiForLua`.

2. Added `logIdRef.current = 0` in the `handleStart` callback to reset the log ID counter.

3. Completely rewrote `step-processing.tsx` to include a 3-column layout with: browser panel (left), data table (center), and log panel (bottom). Browser panel simulates loading/typing/form/done phases with visual animations.

## Prevention

- When using Lua parsers with non-ASCII text, always test with the target language (Cyrillic, CJK, etc.) before shipping
- When resetting component state for "restart" functionality, ensure ALL refs are reset, not just state
- For demo/playground features showing "AI processing", always include visual feedback (browser, progress indicators) — text-only logs are insufficient for user understanding
